# 自动测试与发布

更新时间：2026-09-06 14:29（Asia/Shanghai）

## 仓库与触发条件

仓库：<https://github.com/MichengAI/dsh-btw>，默认分支 `main`。

| 入口 | 行为 |
| --- | --- |
| 推送 `main` 或提交 Pull Request | Node.js 22、24 类型检查、单元测试、真实宿主运行时测试和构建；Node.js 24 额外执行 Chromium 桌面及移动端回归。 |
| Actions → 发布 → Run workflow | 默认 `dry_run=true`，执行相同测试、版本说明校验和打包，上传工作流产物，不创建 Release、不发布 npm。 |
| 推送 `v*` 标签 | 测试通过后校验版本、生成双语说明、打包并创建 GitHub Release；npm 发布受仓库变量控制。 |

正式发布要求标签严格等于 `v` 加 `package.json` 版本。`CHANGELOG.zh-CN.md` 和 `CHANGELOG.md` 必须各自包含唯一且非空的同版本章节。Release 标题为版本标签，正文为中文在前、英文在后，与两份 CHANGELOG 对应章节一致。

## npm Trusted Publishing

发布工作流为 `.github/workflows/publish.yml`，使用 GitHub OIDC，不在仓库保存 npm 令牌。

新仓库默认设置 `NPM_PUBLISH_ENABLED=false`：GitHub Release 和安装包可独立发布。完成 npm 端设置后再启用：

1. 确认 npm 包 `@michengai/dsh-btw` 已创建并归当前发布者管理；尚未创建时，按 npm 当前要求先完成首次发布。
2. 在 npm 包设置的 Trusted Publisher 中选择 GitHub Actions，填写组织或用户名 `MichengAI`、仓库 `dsh-btw`、工作流文件 `publish.yml`，不指定 Environment。
3. 在 GitHub 仓库 Actions Variables 中将 `NPM_PUBLISH_ENABLED` 改为字符串 `true`。

启用后通过 Node.js 24 自带的新版 npm 执行 `npm publish <安装包> --access public --provenance`。首次启用前确认 npm 支持当前 CLI 的 OIDC。不要以任意新增版本号作为测试手段。

同一 npm 版本不能覆盖。若 npm 已成功发布而后续 Release 步骤失败，可暂时关闭 npm 发布开关，再重跑标签工作流，恢复 GitHub Release 和附件；不要改写已经共享的标签。

## 发布步骤

先更新 `package.json`、锁文件及两份 CHANGELOG，完成审核和提交推送。推荐先在 Actions 手动运行默认的 dry run，确认产物内容，再创建标签。

```powershell
[Console]::OutputEncoding = [System.Text.Encoding]::UTF8
$OutputEncoding = [System.Text.Encoding]::UTF8

$releaseVersion = (Get-Content package.json -Raw -Encoding UTF8 | ConvertFrom-Json).version
git tag "v$releaseVersion"
git push origin "v$releaseVersion"
```

工作流测试失败时不会进入发布阶段。`scripts/check-package.mjs` 校验实际 tar 包中的入口、类型、截图、更新日志以及文件范围。

## 提交与产物范围

提交源码、测试、浏览器模拟宿主、构建配置、锁文件、Actions、项目文档和 README 截图。模拟宿主 `preview` 是浏览器测试的依赖，并非用户独立使用页面。

`node_modules`、`lib`、`dist`、`artifacts`、测试报告、缓存、日志、环境变量文件、备份和 `.tgz` 不进入 Git。截图交付物位于 `assets/screenshots`；自动截图保存在被忽略的 `artifacts`，CI 失败时作为工作流证据保留 7 天。

本地与 CI 均使用锁文件中的官方 npm 下载地址，沿用项目的 `legacy-peer-deps=true`。CI 通过 `DSH_RUNTIME_ROOT` 指向开发依赖中的真实运行时，不依赖机器预装的 DSH，也不读取模型凭据。

## 恢复

仓库代码通过正常修复提交恢复，不强制推送。停止 npm 发布时将 `NPM_PUBLISH_ENABLED` 设为 `false`。已发布 npm 版本不能通过代码回退覆盖，修复后发布新版本；已安装客户端可按需要安装此前可用版本。
