# 客户端注入与气泡宽度修复

更新时间：2026-09-06 12:26（Asia/Shanghai）

## 问题与根因

用户在真实 DSH 提交旁问时，气泡显示 `Error: cannot get property "remote.commands" without inject`。客户端仅声明 `remote`，缺少 Cordis 对命名空间服务要求的独立 `remote.commands` 注入。官方命令客户端也显式声明这两个服务。此前普通对象模拟没有覆盖真实注入权限检查。

截图中气泡横跨窗口。插件挂载在输入区域 dock，但未应用宿主输入框的宽度限制与水平留白。

## 修复

- `src/client/index.tsx` 补充 `remote.commands` 注入声明。
- `src/client/styles.ts` 使用宿主的 `--dsh-composer-card-max-width` 和 `--dsh-composer-side-clearance` 限制宽度并居中。
- `tests/client-injection.test.ts` 用真实 Cordis Context、Service 与独立提供命令服务的插件验证提交路径。保留属性读取以触发注入检查；不能使用绕过检查的 `ctx.get()`。
- 浏览器测试检查构建包注入声明，以及桌面和移动端气泡与输入框的宽度、水平位置。

## 验证与交付
